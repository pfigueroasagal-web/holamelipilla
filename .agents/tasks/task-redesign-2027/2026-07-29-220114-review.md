# Palette shift from forest green to navy/teal/amber

The landing page's entire color system was replaced — moving from a warm forest-green (#1B4332) palette with orange (#F77F00) accents to a slate/navy (#0f172a) base paired with teal (#0f766e, #2dd4bf) and warm amber (#f59e0b). The change touches CSS custom properties, inline SVG gradients, component-specific styles, dark mode overrides, and inline styles baked into `index.html`. The approach is a find-and-replace at the token level rather than a refactor of how colors are structured, which keeps the diff large but the risk low.

**Watch for:** Inline hardcoded colors in `index.html` that bypass CSS variables create a maintenance fork (confirmed). The mega-turno badge flipped from white text on orange to dark text (#78350f) on a lighter amber gradient — verify this meets WCAG AA against the background at smaller badge sizes (likely). Dark-mode ferias page-header may have insufficient contrast in its deepest stop (#022c22 on dark backgrounds) (possible).

## High-level view

The palette swap is purely cosmetic, executed by remapping every color token in `:root` and propagating the new values through ~315 changed lines across both files. The structural CSS — layout, spacing, typography scale, animation curves, grid definitions — is untouched. The nav shifts from an opaque gradient to a glassmorphism approach with a semi-transparent navy base, but two competing nav declarations exist in the file (early block and 2027 polish block) with subtly different opacity and saturation values.

Where the old palette hard-coded `#1B4332` and `#F77F00` in both `styles.css` variables and inline HTML `style=""` attributes, the new code duplicates the same pattern: CSS variables exist, but several key components (the bienvenida box, the avisos card) bypass them with inline hex values — and the avisos-card actually regressed from referencing `var(--primario)` to a hardcoded value.

Dark-mode overrides were updated consistently across all four `@media (prefers-color-scheme: dark)` blocks, and subpage header gradients got matching treatment for both light and dark variants across all five section themes.

## Inline color duplication vs. CSS variable system

The `:root` block defines `--primario: #0f766e` and `--primario-medio: #0d9488`, yet `index.html` line 452 writes the bienvenida gradient as a raw inline style:

```html
<div style="background:linear-gradient(135deg,#0f766e,#0d9488);border-radius:20px;...">
```

The avisos card in `styles.css` does the same:

```css
.avisos-card{background:linear-gradient(135deg,#0f766e,#0d9488);...}
```

The old code had the same structural issue with the inline HTML, but the `.avisos-card` class previously referenced `var(--primario)` and `var(--primario-medio)`. This diff regresses that class to hardcoded values, making the disconnect worse. A future palette change now has three places to update instead of two.

## Nav glassmorphism: competing declarations

The nav gets styled twice in the cascade. The primary block (around line 62 in styles.css) sets:

```css
background: linear-gradient(135deg, rgba(15,23,42,.92) 0%, rgba(30,41,59,.92) 100%);
backdrop-filter: saturate(180%) blur(18px);
```

The 2027 polish block (~line 2889) overrides with:

```css
background: linear-gradient(135deg, rgba(15,23,42,.88) 0%, rgba(30,41,59,.88) 100%);
backdrop-filter: saturate(160%) blur(16px);
```

Only the latter takes effect. The first declaration is dead code that will confuse anyone who reads it expecting it to be the source of truth. Either consolidate into one declaration or leave a comment at the first one indicating the override.

## Mega-turno badge accessibility shift

The badge moved from `color: #fff` on `#F77F00` (contrast ratio ~4.5:1, borderline AA) to `color: #78350f` on a gradient from `#f59e0b` to `#fbbf24`. The darker end gives ~4.9:1 (passes), but the lighter end `#fbbf24` against `#78350f` drops to approximately 3.8:1. At 11px font-size with `font-weight: 800`, the effective rendering is small text per WCAG definitions. The gradient midpoint covers most badge area so practical legibility is probably fine, but the lighter stops at badge edges fail the threshold. Bumping text color to `#57200b` or darkening the lighter gradient stop to `#f5a623` would close the gap.
